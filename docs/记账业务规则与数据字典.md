## 1. 规则优先级与名词

PRD 已确定规则 > 经确认 ADR > 本文推荐设计。未确认推荐不可当作已发布协议。收支结余指周期收入减支出，账户总余额包含初始余额和历史资金流，两者不可混用。“有效”指未被删除/撤销且已提交的记录；暂存/失败/预览记录不得参与聚合。

- 收支金额为正整数分，类型 income/expense 指定方向；展示元两位小数。
- 初始余额与账户余额可为负是推荐方案（D-03/D-04），非新增账户类型。
- 账单发生时间用于区间归属，创建时间用于审计；编辑发生时间不修改创建时间。
- 用户界面按设备本地日期展示，持久化时区/偏移和跨端解释待 D-06 确认，不提前固定协议。
- 日期边界两端包含、内部半开区间为 D-05 建议；日均按日历天数包含零消费日也待确认。
- 后端、认证、租户、云同步、银行卡号与账号类型字段不属于目标模型。

## 2. 逻辑数据字典（计划，不是当前数据库列名）

所有实体使用独立稳定 ID，不以可编辑名称作为引用；实际字段名和本地键映射在 Task 2 冻结。整数总和也需安全范围校验。创建/修改时间由应用生成，历史未知创建时间应标明来源，不能虚构。

| 实体 | 逻辑字段与约束 | 关系/计算规则 | 未决项 |
| --- | --- | --- | --- |
| Account | id；name 必填；initialBalanceCents 可空，计算按0；createdAt/updatedAt | 可关联账单、转入、转出；无 accountType；禁止收集真实卡号等信息 | 名称上限/重名规则 D-04/D-09；负值/信用卡 D-03 |
| Category | id；name；direction income/expense；iconKey；sortOrder | 账单引用其 ID；有账单时不允许直接切方向；分类迁移只允许同方向 | 名称、图标映射、删除策略 D-04/D-06/D-09 |
| Transaction | id；direction；amountCents 正整数；accountId；categoryId；occurredAt；note 可空；createdAt/updatedAt；删除状态 | 账户/分类必须存在且方向合法；编辑改账户/日期需让两侧聚合失效 | 金额上限 D-04；未来时间 D-05；历史时间缺失方案 Task 2 |
| Transfer | id；fromAccountId；toAccountId；amountCents 正整数；occurredAt；createdAt/updatedAt；撤销状态 | 两端不同且存在；原子提交；不生成收入/支出账单 | 信用卡 D-03；删除关联 D-09；备注等附加字段待设计评审 |
| Budget | id；scope 总额/分类；categoryId 分类时必填；amountCents 正整数；period；start/end | 仅符合方向、分类、日期范围的有效支出参加；总/分类预算独立计量 | 周期、重复/重叠、边界 D-05 |
| Attachment | id 或稳定引用；ownerId；sandboxPath/交换清单引用；媒体类型/大小 | 仅允许沙箱受控路径；导入先暂存，提交后生效；保留旧日记/凭证 | 交换编码/大小与旧内容 D-02/D-06 |
| ImportBatch | stableBatchKey；sourceFormat/schemaVersion；status；计数/摘要 | 批次与账单同事务提交，防崩溃后重复；指纹只标记疑似重复 | 合并/替换、指纹和冲突处理 D-06 |

余额投影=初始余额+有效收入−有效支出+有效转入−有效转出。若缓存投影，必须在同事务更新且能重建；没有独立人工修正余额入口。预算剩余=预算额−已用支出，使用率=已用/预算额×100%；超支剩余为负、百分比允许大于100%，进度条宽度可封顶。

## 3. 当前模型到目标模型的已知差距

- Flutter 数据库版本为4，`ledger_transactions.amount` 与 `ledger_accounts.balance` 为 REAL；已有账户/分类本地 ID 和创建时间。迁移必须先明确 balance 语义，保留旧 ID 映射与附件引用，转换差异单列，不直接乘100后截断。
- Flutter `LocalDataApi` 的账单创建/修改/删除方法未构成余额管理闭环，图片持久化与账单写入不能据现状推断为完整事务。
- 鸿蒙 AppData v1 已存整数分，账单按账户/分类字符串引用，缺独立 Account/Category 实体；需要分方向将分类名称映射到新 ID，同名不同方向不能合并。
- 鸿蒙存储为整份 JSON；切换 RDB 或继续 JSON 须 D-07 决策，不可先引入某一套正式迁移。
- 两端旧备份格式不互通；不能将某端 JSON 的 version 直接解释为新通用 schemaVersion。

## 4. 隔离验收样例（仅人工构造，无真实数据）

本节即 Task 1 的确定性验收数据定义，未写入生产数据库。测试实现由后续 Task 创建；此处计算核对不等于应用测试通过。

### 4.1 主流程样例 F-BASE

日期统一选 `2026-11-16`，两个普通账户 A/B；支出分类“餐饮”、收入分类“工资”；总预算100元（周期包含当天）。ID 使用测试专用 `fixture-account-a`、`fixture-account-b`、`fixture-category-food`、`fixture-category-salary`，不作为正式 UUID 协议。

| 步骤 | 操作 | A余额（分） | B余额（分） | 总余额（分） | 收入/支出（分） | 预算剩余（分） |
| --- | --- | ---: | ---: | ---: | --- | ---: |
| 0 | A初始100000，B初始留空 | 100000 | 0 | 100000 | 0/0 | 10000 |
| 1 | A收入20000 | 120000 | 0 | 120000 | 20000/0 | 10000 |
| 2 | A餐饮支出8000 | 112000 | 0 | 112000 | 20000/8000 | 2000 |
| 3 | A转B 5000 | 107000 | 5000 | 112000 | 20000/8000 | 2000 |
| 4 | 将原支出由8000改为3000 | 112000 | 5000 | 117000 | 20000/3000 | 7000 |
| 5 | 删除该支出 | 115000 | 5000 | 120000 | 20000/0 | 10000 |
| 6 | 撤销转账 | 120000 | 0 | 120000 | 20000/0 | 10000 |

每个扩展用例从对应行隔离复制状态，不串联污染；原始主样例固定为步骤3。补录 B 初始余额10000后，从步骤3派生：A=107000、B=15000、总额122000，收入/支出及预算不变。

### 4.2 边界样例

| ID | 人工数据/操作 | 应验证的结果 |
| --- | --- | --- |
| F-CENT | 0.10元与0.20元两笔支出 | 总支出30分，不出现浮点尾差；展示0.30 |
| F-MONTH | 2026-10-31 23:59支出100分；2026-11-01 00:00支出200分 | 按本地日历月统计分别100/200，不跨界重复；时区协议 D-06 后补偏移样例 |
| F-LEAP | 2024-02-29与2025-02-29 | 前者有效、后者拒绝；未来日期策略单独按 D-05 |
| F-SAME-TIME | 120笔同一发生时间、不同稳定ID账单，每笔100分 | 总额12000；每页50条共3页，不重不漏；具体ID排序规则 Task 6 冻结 |
| F-NEGATIVE | 账户初始−10000分，无其他记录 | 推荐余额−10000，不记支出；此预期待 D-03/D-04确认 |

| F-MIGRATION | 每种旧库版本/旧鸿蒙JSON各一份人工样例，含日记和附件 | 条数/金额/关系/附件保留，重复迁移不重复，故障保留旧快照；正式文件由 Task 2 创建 |

### 4.3 失败与恢复约束

测试从隔离快照开始；发生失败后同时核对记录数、关联、金额、附件和界面通知，不能只看错误提示。提交成功但通知前进程终止，重启应读到已提交状态；提交未成功则全部保持原状态。任何测试不允许覆盖开发者已有真实沙箱。
