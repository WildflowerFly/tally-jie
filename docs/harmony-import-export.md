# Harmony 数据导入导出协议

更新时间：2026-11-17。入口：我的 → 数据导入导出。与Flutter备份不兼容。所有导入先预览，确认后合并，不覆盖冲突记录，不恢复日记功能。

## 四种模式

| 模式 | 格式 | 适用范围 |
| --- | --- | --- |
| 完整可移植备份（默认） | JSON，`format=TallyJie-Portable`、`version=1`，含data与files | 账户/分类/收支/转账/预算/附件元数据、图片Base64、旧JSON和日记图片归档；空沙箱重建使用此模式 |
| 账本元数据 | JSON，`format=TallyJie-Ledger`、`version=2`，data模型v2 | 六类实体，不含附件字节；目标缺附件时拒绝，不是完整备份 |
| 全实体关联表 | BOM UTF-8 CSV，列为`schema,entity,payload` | schema每行2；entity为accounts/categories/entries/transfers/budgets/attachments；payload为完整实体JSON，全部字段/整数分/时间戳保留。不含附件字节 |
| 收支CSV / 自定义映射 | BOM UTF-8 CSV，默认列见下 | 已有账户和分类，导入前可映射列名；导出可按日期范围；不含转账/预算/账户初始余额/附件 |

完整备份与关联数据均全量，不以日期裁剪破坏余额和引用。只有收支CSV支持包含首尾的日期范围。

## 收支CSV映射

默认表头：`id,type,amount,accountId,categoryId,date,time,note`。

- 8个字段均需唯一对应列（备注可为空但需有列）；不静默猜测第三方格式。
- id必填且稳定，type支持income/expense或收入/支出；amount是正十进制元，内部整数分；date为YYYY-MM-DD，time为HH:mm。
- 账户及分类值可使用已有ID或唯一名称；分类必须与收支类型一致。不自动创建或推断账户初始余额。
- 支持中文、BOM、引号、逗号、引号内换行、CRLF。导出对公式起始字符添加单引号，导入对本协议转义还原；原有单引号相同规则加倍，往返不丢。
- 汇总行级错误，每页50项；行号是CSV逻辑记录号（表头1），不等于含换行字段的物理文本行。任一行错误不生成可提交预览；最终余额/整体引用错误标记“整体账本”。
- 同ID同业务字段跳过，不要求CSV提供创建时间；同ID异内容拒绝整批。新CSV记录创建时间null，不伪造历史创建时间。

## 合并、来源与事务

- JSON/关联表同ID同内容跳过，不同内容拒绝；对象属性顺序不构成内容差异。所有最终引用、预算重叠、余额均需通过校验。
- 文件原始文本SHA256作为来源收据，与账本变更和revision在同一数据库事务中提交；相同来源再次导入拒绝重复写入。即使文件内容重新排版导致SHA不同，实体ID仍保护幂等。
- 预览和实际提交之间revision变化需重新预览；不会用旧快照覆盖新账本。取消预览不写入。
- 可移植文件仅允许`images/img_*.jpg`与`legacy/tallyjie.json`/`legacy/<64位SHA256>.json`，禁止穿越/绝对路径/重复路径/非法Base64。
- 同路径已有文件必须字节相同，否则拒绝，不改名覆盖。外来历史JSON写入`filesDir/imported-legacy/<内容SHA256>.json`，不冒充当前v1迁移源；再次导出包含所有归档和它们引用的图片。
- 新文件写入前持久化exchange-journal.json；写文件成功后事务提交数据与来源收据；启动/操作完成时检查收据，已提交保留，未提交删除仅本次新建文件。既有文件不删除。实际文件系统断电持久性仍需设备实测。

## 限额及处理

- 文件字节限额：完整备份64MB，元数据/关联CSV16MB，收支CSV8MB；导出编码后也检查，防止生成本端无法读回的大文件。
- 单图8MB、单旧JSON16MB、附件字节总40MB、文件数2000；CSV最大100000条数据记录。
- 文件异步64KB分块读写，短读/短写处理，写后fsync；导入数据库采用差量异步写入，一个事务提交，不能将部分批次发布为成功。
- JSON序列化与CSV解析仍在上述限额内整体驻留内存，不是无上限流式处理。超限应缩小收支导出范围/独立保存原归档，而不是绕过校验。
- 导出到外部目标失败可能遗留不完整文件，页面明确提示删除后重试；不会修改源账本。外部文件由用户保管，包含敏感财务数据。
