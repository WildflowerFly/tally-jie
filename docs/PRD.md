# 个人记账 App 产品需求文档（PRD）

**文档版本：** V1.0  
**产品类型：** 移动端个人记账应用  
**产品定位：** 轻量化、本地化、简约金融风格的个人记账工具  
**核心原则：** 无需登录、数据本地存储、操作简单、账目清晰

---

# 一、产品概述

## 1.1 产品背景

随着日常消费方式越来越多样化，个人资金可能分散在微信、支付宝、银行卡、信用卡及现金等不同账户中。用户需要一个简单直观的工具，记录日常收入和支出，了解不同账户的资金情况，并通过统计分析掌握个人消费习惯。

本产品旨在提供一款轻量级个人记账应用，不引入复杂的账本、社交、云同步等功能，将重点放在日常记账、账户管理、收支统计和预算控制上。

## 1.2 产品目标

1. 提供快速、便捷的收入和支出记录功能。
2. 支持多个自定义账户，统一管理不同资金渠道。
3. 实时展示各账户余额及账户资金变化。
4. 通过统计图表分析个人收入、支出和消费结构。
5. 支持预算设置，帮助用户控制日常消费。
6. 支持本地数据导入和导出，保障用户对个人数据的自主控制。

## 1.3 产品设计原则

- **简单：** 减少不必要的功能和操作步骤。
- **直观：** 使用清晰的金额展示和可视化统计。
- **本地化：** 不需要注册登录，数据全部存储在设备本地。
- **统一：** 所有页面采用一致的视觉语言和交互规范。
- **轻量：** 不设置复杂的账本体系、账户类型体系和冗余设置页面。

## 1.4 用户范围

主要面向有个人收支记录需求的用户。

典型使用场景：

- 记录日常购物、餐饮、交通等消费。
- 记录工资、兼职、奖金等收入。
- 查看微信、支付宝、银行卡等账户余额。
- 查看每月收入、支出和消费分类。
- 设置每月消费预算。
- 导出个人账单进行留存或进一步分析。

# 三、整体 UI 与视觉设计规范

## 3.1 设计风格

整体参考用户提供的金融账户管理界面，采用简约、现代、轻量化的金融产品设计风格。

主要视觉特点：

1. 以黑色、白色和浅灰色为主要配色。
2. 页面使用大面积留白，避免信息堆叠。
3. 使用圆角卡片承载核心信息。
4. 重点金额采用较大字号和较高字重。
5. 账户卡片采用深色渐变和层叠效果。
6. 重要操作使用简洁图标。
7. 底部导航采用圆角悬浮式黑色导航栏。
8. 统计页面采用简洁的图表和数据卡片。

## 3.2 色彩规范

| 使用场景 | 建议颜色 |
|---|---|
| 页面背景 | #F5F5F5 |
| 卡片背景 | #FFFFFF |
| 主文字 | #171717 |
| 次级文字 | #888888 |
| 辅助文字 | #B0B0B0 |
| 主操作色 | #171717 |
| 深色卡片 | #202020 |
| 深色卡片渐变 | #303030 至 #111111 |
| 收入金额 | #269B73 |
| 支出金额 | #E16C61 |
| 分割线 | #EEEEEE |

收入和支出使用适当的颜色区分，但整体仍保持黑白灰为主的视觉风格。

## 3.3 卡片设计

- 普通信息卡片使用白色背景。
- 卡片采用较大的圆角。
- 卡片之间保持适当间距。
- 重点金额使用大字号。
- 账户卡片采用深色渐变背景。
- 多个账户卡片可以采用前后层叠的视觉效果。
- 卡片内文字和图标保持足够的对比度。

## 3.4 导航栏设计

采用底部悬浮式黑色圆角导航栏。

导航栏从左至右：

1. 统计
2. 明细
3. 记账
4. 存款
5. 我的

设计要求：

- 黑色或深灰色背景。
- 较大的圆角。
- 白色图标和文字。
- 当前选中页面使用更明显的视觉状态。
- 导航栏固定在屏幕底部。
- 适配不同尺寸的移动设备和底部安全区域。

记账页面作为默认启动页面，但仍保留五个导航入口。

# 四、功能需求详细说明

# 4.1 统计页面

## 4.1.1 页面定位

统计页面用于展示用户的整体收支情况，通过金额卡片、趋势图和分类占比图帮助用户了解自己的资金变化和消费习惯。

## 4.1.2 页面功能

### A. 收支概览

展示指定统计周期内的核心财务数据。

主要信息：

- 总收入
- 总支出
- 收支结余

计算规则：

收支结余 = 总收入 - 总支出

默认展示当前月份的数据。

支持切换：

- 本周
- 本月
- 本年
- 自定义时间范围

### B. 收入分析

展示选定时间范围内的收入情况。

主要内容：

- 收入总额
- 收入趋势
- 收入分类占比
- 收入来源排行

支持按照日、周、月查看收入变化。

### C. 支出分析

展示选定时间范围内的支出情况。

主要内容：

- 支出总额
- 支出趋势
- 支出分类占比
- 支出分类排行

帮助用户了解主要消费方向。

### D. 分类占比

采用环形图或饼图展示各个分类的金额占比。

例如：

- 餐饮
- 购物
- 交通
- 娱乐
- 住房
- 医疗
- 其他

点击图表中的分类，可以查看该分类对应的账单明细。

### E. 消费分析

展示用户的消费变化情况。

主要内容：

- 每日消费趋势
- 每月消费趋势
- 消费最高的分类
- 消费最高的日期
- 平均每日支出
- 消费排行

统计周期和数据范围应与当前选择的时间范围保持一致。

## 4.1.3 页面交互

- 点击收入金额进入收入明细。
- 点击支出金额进入支出明细。
- 点击分类图表进入对应分类的账单列表。
- 点击趋势图中的数据点查看对应日期的账单。
- 切换时间范围后，所有统计数据同步更新。

# 4.2 明细页面

## 4.2.1 页面定位

明细页面用于统一管理所有收入和支出记录，是用户查询、修改和删除账单的主要入口。

## 4.2.2 页面功能

### A. 账单列表

采用按日期分组的列表形式展示账单。

每条账单主要展示：

- 分类图标
- 分类名称
- 备注信息
- 所属账户
- 账单时间
- 账单金额

金额显示规则：

- 支出：-100.00
- 收入：+5000.00

每日账单分组顶部展示：

- 日期
- 当日收入
- 当日支出

页面顶部展示当前筛选范围内的收支汇总。

### B. 搜索账单

支持通过关键词搜索账单。

搜索范围：

- 分类名称
- 备注内容
- 账户名称

### C. 筛选账单

支持以下筛选条件：

- 收入
- 支出
- 全部类型
- 账户
- 分类
- 开始日期
- 结束日期
- 金额范围

支持多个筛选条件组合使用。

### D. 账单详情

点击某一条账单，进入账单详情页面。

展示：

- 收支类型
- 金额
- 分类
- 所属账户
- 日期和时间
- 备注
- 创建时间

提供编辑和删除操作。

### E. 编辑账单

允许用户修改：

- 金额
- 分类
- 账户
- 日期
- 时间
- 备注

修改账单后，相关账户余额、统计结果和预算使用情况需要同步更新。

### F. 删除账单

用户点击删除后，需要进行二次确认。

删除完成后：

- 从账单列表移除。
- 重新计算账户余额。
- 更新统计数据。
- 更新预算使用情况。

### G. 预算入口

明细页面提供预算入口。

点击后进入预算管理页面，可以查看和修改预算。

# 4.3 记账页面

## 4.3.1 页面定位

记账页面是整个应用最核心的功能页面，主要用于快速记录用户的日常收入和支出。

打开应用时默认进入此页面。

## 4.3.2 页面结构

页面顶部：

- 页面标题
- 当前日期

主要内容：

- 收入/支出切换
- 金额输入区域
- 分类选择区域
- 账户选择区域
- 日期选择
- 备注输入
- 保存按钮

## 4.3.3 收支类型切换

提供两个选项：

- 支出
- 收入

选择不同类型后，分类列表自动切换。

支出分类示例：

- 餐饮
- 购物
- 交通
- 娱乐
- 住房
- 医疗
- 教育
- 其他

收入分类示例：

- 工资
- 奖金
- 兼职
- 理财收入
- 退款收入
- 其他

具体分类支持用户自行管理。

## 4.3.4 金额输入

提供数字键盘输入金额。

要求：

- 支持整数和小数。
- 最多保留两位小数。
- 支持删除输入内容。
- 金额必须大于 0。
- 未输入金额时不允许保存。

金额采用清晰醒目的大字号展示。

## 4.3.5 分类选择

- 根据当前收支类型展示对应分类。
- 支持选择分类图标。
- 支持进入分类管理页面。
- 支持用户自定义分类。

## 4.3.6 账户选择

展示用户创建的所有账户。

例如：

- 微信
- 支付宝
- 招商银行储蓄卡
- 招商银行信用卡
- 现金

用户选择本次交易对应的账户。

## 4.3.7 日期选择

默认使用当前日期和时间。

支持修改：

- 年份
- 月份
- 日期
- 时间

允许补录过去发生的账单。

## 4.3.8 备注

备注为选填字段。

用户可以填写消费用途、收入来源等信息。

## 4.3.9 保存账单

点击保存后：

1. 校验金额是否合法。
2. 校验分类是否已选择。
3. 校验账户是否已选择。
4. 保存账单到本地。
5. 更新对应账户余额。
6. 更新统计数据。
7. 更新预算使用情况。
8. 返回记账页面或清空当前输入内容，供下一笔记账使用。

# 4.4 存款页面

## 4.4.1 页面定位

存款页面用于统一展示用户创建的各个资金账户，帮助用户快速了解不同账户的余额和资金变化。

页面视觉设计重点参考用户提供的银行卡管理界面。

整体采用深色账户卡片、浅色背景、层叠卡片效果以及简洁的账户账单列表。

## 4.4.2 页面结构

页面主要分为四个区域：

1. 页面顶部区域
2. 账户总余额区域
3. 账户卡片展示区域
4. 当前账户收支记录区域

### A. 页面顶部

展示：

- 页面标题
- 账户管理入口

### B. 账户总览

展示所有账户的汇总余额。

主要内容：

- 账户总余额
- 账户数量

账户总余额按照所有账户当前余额相加计算。

需要注意：不同账户之间的转账不属于收入或支出，但会改变对应账户的余额。

### C. 账户卡片展示

采用参考图中的银行卡视觉设计。

设计要求：

- 深色渐变背景。
- 大圆角卡片。
- 大字号余额。
- 显示账户名称。
- 多账户之间采用前后层叠效果。
- 当前选中账户位于视觉中心。
- 支持左右滑动切换账户。

卡片展示内容：

- 当前余额
- 账户名称

不展示真实银行卡号、有效期、持卡人姓名等信息。

原因是本产品仅用于个人账目管理，不需要收集或存储真实银行卡信息。

### D. 账户切换

用户左右滑动账户卡片，可以切换当前选中的账户。

切换后：

- 当前选中账户变化。
- 卡片余额同步更新。
- 下方账单列表同步更新。
- 账户收支统计同步更新。

### E. 账户收支记录

选中账户后，在下方展示该账户的部分账单记录。

每条记录展示：

- 分类图标
- 分类名称
- 备注
- 交易日期
- 交易金额

默认展示最近的账单。

提供查看全部入口，点击后进入该账户对应的完整账单列表。

### F. 账户详情

点击账户卡片进入账户详情页面。

展示：

- 账户名称
- 当前余额
- 初始余额
- 累计收入
- 累计支出
- 最近交易记录

提供账户编辑和账户删除入口。

### G. 账户余额计算

普通账户余额计算：

当前余额 = 初始余额 + 累计收入 - 累计支出 + 转入金额 - 转出金额

其中，初始余额允许为空。

当用户创建账户时未填写初始余额：

- 初始余额按 0 元处理。
- 当前余额显示 0 元。
- 后续允许随时补录初始余额。

补录或修改初始余额后，需要重新计算账户当前余额。

**注意：信用卡消费和还款的余额计算规则，需要在产品规则确认后进一步细化。**

# 4.5 我的页面

## 4.5.1 页面定位

我的页面用于集中管理应用中的基础数据和预算功能。

不设置隐私设置、外观设置和其他设置。

## 4.5.2 页面功能

### A. 账户管理

用户可以创建、编辑和删除账户。

账户字段：

| 字段 | 是否必填 | 说明 |
|---|---|---|
| 账户名称 | 是 | 用户自定义名称 |
| 初始余额 | 否 | 创建时可以留空 |

账户名称示例：

- 微信
- 支付宝
- 招商银行储蓄卡
- 招商银行信用卡
- 中国银行储蓄卡
- 工商银行信用卡
- 现金

账户不设置账户类型字段。

账户初始余额规则：

- 允许为空。
- 留空时显示 0 元。
- 后续可以随时补录或修改。
- 修改初始余额后重新计算当前余额。

账户删除规则：

- 删除账户前进行二次确认。
- 已经存在账单的账户，不允许直接删除并丢失历史记录。
- 应提供账单迁移或先处理关联账单的操作。
- 不允许删除后导致历史账单失去账户关联。

### B. 分类管理

用于管理收入分类和支出分类。

主要功能：

- 查看收入分类。
- 查看支出分类。
- 新增分类。
- 编辑分类。
- 删除分类。
- 修改分类名称。
- 修改分类图标。
- 调整分类排序。

分类分为收入分类和支出分类，两者分别管理。

删除已有账单关联的分类时，需要避免历史账单数据丢失。

### C. 预算管理

用于设置和管理个人消费预算。

主要功能：

- 设置总支出预算。
- 设置分类预算。
- 设置预算周期。
- 查看预算使用情况。
- 查看剩余预算。

预算类型：

1. 总预算：控制某个周期内的全部支出。
2. 分类预算：控制某个周期内指定分类的支出。

预算计算：

预算剩余金额 = 预算金额 - 已使用金额

预算使用率 = 已使用金额 / 预算金额 × 100%

预算周期建议支持：

- 每月
- 每周
- 自定义周期

预算页面展示：

- 预算金额
- 已使用金额
- 剩余金额
- 使用进度条

### D. 数据导入

用于将外部账单数据导入本地应用。

建议支持 CSV 格式，后续可以根据需要扩展其他格式。

导入流程：

1. 选择导入文件。
2. 解析文件内容。
3. 展示待导入数据预览。
4. 检查数据格式。
5. 提示异常数据。
6. 用户确认导入。
7. 保存到本地数据库。
8. 更新账户余额和统计数据。

导入过程中需要防止重复导入。

### E. 数据导出

用于将应用内的个人账单导出到设备。

建议支持：

- CSV 格式：方便使用 Excel 等软件查看和分析。
- JSON 格式：用于完整保存和迁移应用数据。

导出范围：

- 全部账单
- 指定时间范围账单
- 全部账户信息
- 全部分类信息
- 全部预算信息

导出前允许用户选择导出范围和文件格式。

# 五、核心业务规则

## 5.1 收支规则

支出记录会增加对应账户的支出金额。

收入记录会增加对应账户的收入金额。

基础计算：

账户余额 = 初始余额 + 收入 - 支出

转账不计入收入和支出统计。

## 5.2 转账规则

建议将账户间转账作为独立的资金流转业务处理。

例如：

从微信转出 500 元到银行卡：

- 微信账户减少 500 元。
- 银行卡账户增加 500 元。
- 总收入不增加。
- 总支出不增加。

这样可以避免将账户间资金转移错误地统计为消费。

## 5.3 预算规则

预算只统计符合预算口径的支出记录。

收入不计入支出预算。

账户转账不计入支出预算。

修改或删除账单后，需要重新计算预算使用情况。

## 5.4 历史账单规则

- 修改账单需要同步更新所有相关数据。
- 删除账单需要同步更新所有相关数据。
- 修改分类名称不应破坏历史账单。
- 删除分类时需要保护已有账单关联。
- 删除账户时需要保护已有账单关联。

## 5.5 金额精度规则

- 所有金额统一使用人民币元展示。
- 金额保留两位小数。
- 内部计算应避免浮点数精度误差。
- 金额为正数，收入和支出方向通过交易类型区分。

# 六、本地数据管理

## 6.1 数据存储原则

应用不需要注册和登录。

所有用户数据保存在当前设备本地。

主要数据包括：

- 账户数据
- 账单数据
- 分类数据
- 预算数据
- 转账数据

## 6.2 数据关联

核心数据关系：

- 一个账户可以关联多条账单。
- 一个分类可以关联多条账单。
- 一个预算可以关联多个统计范围内的支出记录。
- 一笔转账关联转出账户和转入账户。

每条数据需要拥有独立且稳定的唯一标识。

## 6.3 数据导入导出要求

- 导入前进行数据校验。
- 导入失败时不得造成已有数据损坏。
- 导出文件应包含完整的数据字段。
- 导入时应检查重复数据。
- JSON 导出应能够完整保留账户、账单、分类、预算和转账之间的关联关系。

# 十、待确认业务规则

以下内容在进入正式开发前需要进一步确定，避免后续账户余额和统计数据出现计算问题。

## 10.1 信用卡消费和还款

建议采用以下方式：

- 信用卡消费时，直接记录支出。
- 信用卡余额按照消费和还款变化。
- 信用卡还款作为账户之间的资金转移处理，不重复计入支出。

这样可以避免信用卡消费和还款被重复统计。

但该规则仍需用户最终确认。

## 10.2 初始余额补录

已经确定：

- 初始余额可以为空。
- 为空时账户余额显示 0 元。
- 后续允许随时补录或修改初始余额。
- 修改后重新计算当前余额。

## 10.3 账户类型

已经确定：

- 不设置账户类型。
- 不区分资产账户和负债账户。
- 不区分微信、支付宝、储蓄卡、信用卡等账户类型。
- 用户只需要自定义账户名称。

# 十二、产品总结

本产品是一款以个人日常记账为核心的轻量化移动应用。

整个产品围绕五个核心页面展开：

1. **统计：** 让用户了解自己的收入、支出和消费结构。
2. **明细：** 让用户管理和查询所有历史账单。
3. **记账：** 让用户快速记录每一笔收入和支出。
4. **存款：** 让用户直观查看不同账户的余额和资金变化。
5. **我的：** 让用户管理账户、分类、预算和本地数据。

视觉上统一采用参考图中的简约金融设计风格，以黑白灰为主色调，结合深色渐变账户卡片、大圆角组件、层叠卡片和悬浮式底部导航栏。

产品不引入复杂的登录体系、账本体系和账户分类体系，重点保证记账效率、账户余额准确性、统计数据可靠性和本地数据自主性。

**最终产品定位：一款界面简洁、操作流畅、数据完全本地化的个人记账与账户管理工具。**
