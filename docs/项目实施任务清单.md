### 1.2 实施规则

- **顺序**：先写测试或验收用例，运行确认因目标能力缺失而失败，再最小实现、局部验证、全量验证。已有功能先跑特征测试，再增加缺失用例，禁止制造假失败。Task 1 的调研/决策不适合 TDD，以源码核对和评审代替。
- **分层**：Flutter 页面 → 应用服务/`LocalDataApi` → Repository → SQLite；ArkUI 页面 → 应用服务 → Repository → 本地持久化。页面不得直接拼接 SQL、写入备份文件或各自实现余额公式。具体新增文件均为计划路径，不表示已存在。
- **数据**：增量版本迁移，迁移前只读快照、迁移后对账。数据库变更、附件处理和引用关系必须有失败恢复策略。软删除账单不再参与聚合；恢复重复导入不能使余额重复累加。不得删除已有日记、附件、设置和遗留表来满足新界面。
- **金额**：内部统一人民币整数分，输入以十进制字符串解析；收入/支出金额均大于 0，方向由类型决定；初始余额和当前余额允许为负。禁止用二进制浮点参与新业务计算；Flutter REAL 历史数据按 D-04 迁移。跨语言金额及总和不得超过 JavaScript 安全整数范围，超限拒绝而非截断。
- **余额单一真源**：初始余额 + 有效收入 − 有效支出 + 转入 − 转出；优先查询聚合，若做缓存，必须同事务维护并有重建校验。初始余额不计入收入、支出或预算；总余额不是统计页收支结余。
- **一致性**：账单创建/修改/删除、转账、批量迁移和导入只在提交成功后统一通知页面刷新；处理中禁用重复提交，失败保留表单并展示可重试原因；禁止先刷新 UI 再忽略持久化失败。
- **生成文件**：只修改源代码；Flutter 插件注册、构建缓存、HAP/APK/IPA、Hvigor 产物不手工编辑、不纳入业务变更。只有引入代码生成器并经评审后才补充对应 Regenerate 清单和命令；当前不要求新增生成工具。
- **安全**：无登录、无租户、无服务端授权，身份权限类用例不适用；替代检查为沙箱隔离、系统文件授权、附件路径约束、不上传账单、不采集真实卡号/持卡人资料。日志不输出备注、完整账单和备份正文。
- **兼容**：兼容旧数据库和两端各自旧备份；是否实现跨端通用迁移由 D-06 决定。旧导入可并入“数据导入”的格式识别，不保留独立备份恢复一级入口。兼容窗口和退出条件须在 ADR 中确认。
- **文档**：模型、统计口径、导入格式、错误提示和兼容策略随对应任务持续更新，不等待最终任务才补文档；未确认平台 API、信用卡规则和参考图不得写为已支持。
- **授权**：用户已授权按任务执行并逐步勾选，每个 Task 单独 Git 提交，格式 `type(scope): 中文描述`，不推送；仅暂存当前任务文件，保留工作区已有改动。不得安装覆盖用户数据、删除真实数据库、上传数据、签名发布或部署。测试只使用隔离样例，真实数据迁移需另行同意。待决业务规则仍须确认。
